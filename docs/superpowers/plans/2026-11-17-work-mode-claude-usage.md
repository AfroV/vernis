# Work Mode (Claude usage) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opt-in Work Mode that shows the owner's Claude 5-hour and weekly quota left, pushed from their Mac to the frame.

**Architecture:** A stdlib Python LaunchAgent on the Mac reads the Claude Code CLI login from the Keychain, fetches usage, and POSTs only numbers to a token-protected Flask endpoint. `work.html` polls a read endpoint and renders the reference-style "Usage" cards. Menu link, kiosk button and Settings toggle are hidden unless enabled.

**Tech Stack:** Flask (`backend/app.py`), pytest, vanilla HTML/CSS/JS, macOS `security`/`curl`/`launchctl`.

**Spec:** `docs/superpowers/specs/2026-11-17-work-mode-claude-usage-design.md`

## Global Constraints
- Off by default; `GET /api/workmode/config` never returns the push token.
- Only `utilization` (0–100 number) and `resets_at` (ISO string) per window, plus `received_at`, are stored on the Pi.
- Push endpoint: `Authorization: Bearer <push_token>`, `secrets.compare_digest`, 403 when disabled or wrong token; exempt from `_enforce_security` mode gating.
- The Claude token is never printed, logged, put on a command line, or sent to the frame.
- UI text English. No Anthropic mascot/spinner glyph.
- Stale threshold 15 min; poll 60 s; countdown tick 30 s.
- Don't run git (owner handles git) — "Commit" steps are skipped.

## Review Focus
- Push with wrong/missing token or while disabled → 403, nothing stored (tested in Task 1).
- Malformed push body (utilization "abc", 150, missing windows) → 400, previous data kept (Task 1).
- Mode C security on → the Mac's POST still works without a PIN session; `config` POST still needs one (Task 1).
- Reset time already passed and Mac asleep → page shows 100 % left "refilled", not a negative countdown (Task 3, manual check).
- CLI access token expired → script refreshes via the CLI, else exits non-zero with a clear message, never posts zeros (Task 2).
